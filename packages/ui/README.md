# Dispatch interface

`mountGameUi(root, callbacks)` mounts the responsive game shell, menus, settings, HUD, room invites, and results. The UI consumes `UiModel`; its snapshot and scores are read-only projections. Nicknames, errors, room codes, and score rows are written as text, never HTML.

The app supplies semantic callbacks for practice/create/join, start round, resume, leave, rematch, and settings. `onMenuVisibility` must disable gameplay input; local practice can pause its simulation, while online simulation continues. UI copy makes this distinction explicit. Session failures appear in the current menu without requiring developer tools.

Online leaderboards and results show every player's authoritative `pingMs`, including the local player's, with a visible `PING / ms` heading and accessible per-name readouts. Unknown values appear as `—`; solo practice omits the latency column. Results continue following new measurements rather than freezing the first reading.

The persistent header shows a Wi-Fi icon and text for connecting, connected, reconnecting, and connection loss. Reconnecting is amber; disconnected/error states use a slashed icon and `Connection lost`. Accessible names and text convey the state without relying on color. Returning to a connected state clears the slash; local practice uses its neutral local-dispatch label.

Call `update(model)` at HUD cadence. `navigate(action)` accepts keyboard/controller menu actions. `showMenu`, `isMenuVisible`, `getSettings`, `setSettings`, and `dispose` complete the facade. Imported CSS has scoped `fo-` classes, reduced-motion support, and system font fallbacks. No external font stylesheet or font download is requested.

Call `setTargetIndicator(indicator | null)` every rendered frame. `TargetIndicator` supplies canvas-normalized `x`/`y`, clockwise angle from up, `offscreen`, and `distanceMeters`. The UI retains one DOM badge, changes its position/text without layout reads, and shows an outlined `WANTED SUSPECT` badge on screen or stacked directional chevrons with `SUSPECT` and meters off screen. The label remains upright as the arrow turns. Safe border reserves are 84px horizontally, 150px at the top on desktop (104px at widths up to 740px), and 210px above the bottom; these clear the timer/objective and lower instruments. Reduced camera motion and the OS reduced-motion preference remove bobbing and movement transitions. Home, menus, lobby/countdown/results, missing/completed pursuits, and interrupted online connections hide the indicator.

Multiplayer pursuit says `FIRST TO APPREHEND`, explains the three-second close/matched-speed arrest, and shows only the local contender's arrest progress. A rival's global progress is never presented as the local player's. Results use `pursuit.winnerPlayerId`, even when another player leads combat points; no winner means `TIME UP · SUSPECT ESCAPED`. The points leaderboard remains independently ranked. Solo completion opens a case-closed result with `NEW DISPATCH`; its `onRematch` callback must start a fresh practice session.

Pursuit browser fixture: `node packages/ui/dev/pursuit-smoke.mjs` starts and closes its own server on 5187. It verifies local/rival progress, authoritative winner and escape results, solo completion/new dispatch, target visibility, accessible distance, all four screen edges after 1440×900/960×640/520×580 resizing, unchanged DOM nodes, no per-frame rectangle measurements, reduced motion, and explicit north/southwest HUD overlap regressions. Set `CAPTURE_UI=1` for intermediate screenshots under `work/`. This is a DOM fixture; native projection and live multiplayer are validated separately by the renderer and app suites.

The garage assigns one valid random body on fresh storage and persists `{ vehicleBodyId }` under `fender-garage-v1`. `getVehicle()` returns the current assignment; `onPlay` includes it as `vehicleBodyId`. `onVehicleChange(id)` reports user reassignment, always to a different body. Home and the connected online lobby allow reassignment; reconnecting/disconnected states, countdown, live play and results lock it. Lobby snapshots may supply `selectedVehicleBodyId` to synchronize the authoritative choice. A stale connected-lobby snapshot cannot undo a pending user selection. Reconnect/session-epoch changes discard that pending request and resynchronize the confirmed body; leaving the lobby reconciles an accepted or rejected pending selection once, while later in-round snapshots preserve the saved choice. Synchronization does not echo another selection callback. Invalid/corrupted saved values are repaired; unavailable storage still allows a valid in-memory choice.

`isMenuVisible()` and `onMenuVisibility` include the interactive online lobby even though its full menu panel is hidden. This keeps driving input neutral and routes keyboard/gamepad actions to garage/start/invite controls while the server keeps running. The app supplies the selected body to the renderer's garage preview. The UI shows its shared profile name, role, armor, top speed and acceleration/handling meters; HUD integrity is normalized against that body's maximum health.
