# Dispatch interface

Reviewed: 2026-10-26 for `arcade-v13` / protocol 3. *The dispatch desk supplies clues, car keys and a suspiciously cheerful damage report.*

`mountGameUi(root, callbacks)` mounts the responsive game shell, menus, settings, HUD, room invites, and results. The UI consumes `UiModel`; its snapshot and scores are read-only projections. Nicknames, errors, room codes, and score rows are written as text, never HTML.

On larger screens, the quick controls card appears for the first **eight seconds of active keyboard/controller play per mounted page**. Briefings, countdowns, menus, hidden tabs, touch mode, authoritative pause, and interrupted connections suspend its remaining time. HUD updates, device switches, and later dispatches do not restart it. The card follows the local car using the existing viewport/suspect-marker avoidance, shows the current dispatch lesson, and hides fire until the room unlocks guns. Small screens suppress the floating card. Choose **CONTROLS HELP** from the home, pause, results, or campaign briefing menu for the complete layouts and current lesson. Keyboard arrows/Enter and controller menu navigation reach the same action; Escape/controller Back returns to the previous menu. The guide stays open until closed and disables driving through the existing menu callback. Help also respects the unarmed opener and gun unlock.

Both layouts use original DOM/CSS graphics: raised keyboard keycaps, circular controller face buttons, a left stick, triggers, a bumper, and a menu button. Help shows both layouts; the temporary card follows the active device. Keyboard graphics follow current bindings, including remaps, and every action retains a text label. Controller graphics describe the standard mapping using A/X/Y labels. No downloaded artwork or new dependency is needed. The guide scrolls vertically on narrow screens. Run `pnpm exec playwright test tests/e2e/controls-help.spec.ts` for deterministic clock, navigation, remap, responsive/no-overlap, and real server/input checks; screenshots are attached to the browser results. These synthetic checks do not certify physical controllers.
Generic touch controls share the existing device-independent driving actions. `UiSettings.controlScheme` persists Automatic/Touch/Controller/Keyboard. UI owns pointer capture, independent touch IDs and pad geometry, emitting `onTouchInput(TouchControls)`; input owns normalization, action edges and recovery timing. Wire `onTouchCancel` to input reset and input's `onReset` to `resetTouchControls()`. Stale moves after focus/menu/resize/device changes cannot restore held touches. The overlay hides during menus, briefings, results and interrupted connections. Drive with the left pad and hold Fire/Drift on the right; Drift + Fire permits both with one thumb. Compact layouts preserve health, 44px targets and separation from driving HUD. Safe-area insets reserve system edges. Run `pnpm exec playwright test tests/e2e/touch.spec.ts` for Chromium-emulated touch, synthetic-controller handover, persistence, cancellation/resize safety and 1024×768/844×390/390×844 captures under `work/`. These checks do not certify physical mobile hardware or Safari.

The app supplies one `onPlay({roomId,nickname,vehicleBodyId})` callback plus start, resume, leave, rematch, activity and settings callbacks. `onMenuVisibility` disables gameplay input; `isMenuOpen()` distinguishes menus from the briefing for server presence. Authoritative pause state explains solo pause versus a live room with backup. Session failures appear in the current menu without requiring developer tools.

The labeled touch overlay replaces the floating keyboard/controller card in touch mode. Fire and Drift + Fire follow the dispatch-3 gun unlock; the first dispatch remains unarmed. Test contexts explicitly emulate `navigator.maxTouchPoints` from the requested `hasTouch` setting, because installed Chrome may otherwise expose the host's real touchscreen to desktop scenarios.

Fresh storage receives a clean original random callsign from `randomCallsign()`. Generated, rerolled, and custom identities persist as `{ nickname }` under `fender-callsign-v1`; the same shared nickname sanitizer bounds names to 20 characters before dispatch. The home-only `REROLL CALLSIGN` control always chooses a different name, including a bounded fallback when randomness repeats. Editing a callsign changes the next dispatch request; it does not rename an active network player. Missing, malformed, or unavailable storage keeps the UI usable. Initial menu focus remains on `HIT THE STREETS`.

Every campaign dossier includes shared `getBossTactics(dispatchIndex)` information: authored difficulty, driving style, weapon family, and counterplay. The four ringleaders have a stronger visual treatment; the six crew also disclose their gentler attack profiles. The description is authored alongside actual gameplay tuning, so the UI does not invent weaknesses or imply invisible grenade homing.

Online leaderboards and results show every player's authoritative `pingMs`, including the local player's, with a visible `PING / ms` heading and accessible per-name readouts. Unknown values appear as `—`; only legacy local fixtures omit the latency column. Results continue following new measurements rather than freezing the first reading.

The persistent header shows a Wi-Fi icon and text for connecting, connected, reconnecting, and connection loss. Reconnecting is amber; disconnected/error states use a slashed icon and `Connection lost`. Accessible names and text convey the state without relying on color. Returning to a connected state clears the slash; legacy local fixtures use their neutral local-dispatch label.

Call `update(model)` at HUD cadence. `navigate(action)` accepts keyboard/controller menu actions. `showMenu`, `isMenuVisible`, `getSettings`, `setSettings`, and `dispose` complete the facade. Imported CSS has scoped `fo-` classes, reduced-motion support, and system font fallbacks. No external font stylesheet or font download is requested.

Call `setTargetIndicator(indicator | null)` every rendered frame. `TargetIndicator` supplies canvas-normalized `x`/`y`, clockwise angle from up, `offscreen`, and `distanceMeters`. The UI retains one DOM badge, changes its position/text without layout reads, applies the new position directly on every call with no CSS transition (a transition retargeted every frame makes Blink's style recalculation grow for the whole dispatch; `tests/e2e/target-badge-performance.spec.ts` guards this), and shows an outlined `WANTED SUSPECT` badge on screen or stacked directional chevrons with `SUSPECT` and meters off screen. The label remains upright as the arrow turns. Safe border reserves are 84px horizontally, 150px at the top on desktop (104px at widths up to 740px), and 210px above the bottom; these clear the timer/objective and lower instruments. Reduced camera motion and the OS reduced-motion preference remove the arrow bobbing. Home, menus, lobby/countdown/results, missing/completed pursuits, and interrupted online connections hide the indicator.

The full HUD explicitly says `APPREHEND <NAME>`. Automatic arrest instructions, the server's local eligibility guidance and local progress explain how. The temporary floating keycap/controller card and persistent help reflect remapping; fire appears from dispatch 3. Briefings show both actual car previews and the current [tutorial lesson](../../spec/TUTORIAL.md). Results distinguish arrest/wreck outcomes, name the officer and retain earned-only clues.

Compact bounds reserve 60 pixels horizontally, 80 above and 210 below; cached viewport dimensions bypass the full HUD's left-side campaign reservation. No per-frame layout reads are added. Branding, healthy connectivity, speed, standings, campaign tracker, floating tutorials, duplicate arrest instructions and sharing leave the live view. The garage assigns one valid random body on fresh storage and persists `{ vehicleBodyId }` under `fender-garage-v1`. `getVehicle()` returns the assignment; `onPlay` includes it as `vehicleBodyId`. `onVehicleChange(id)` reports reassignment to a different body. The small entry screen only asks for a callsign. Every connected campaign briefing allows reassignment in every server room; reconnecting/disconnected states, countdown, live play and results lock it. Lobby snapshots may supply `selectedVehicleBodyId` to synchronize authority. A stale lobby snapshot cannot undo a pending selection. Reconnect/session-epoch changes discard the pending request and resynchronize the confirmed body; leaving the lobby reconciles it once, while later live snapshots preserve the saved choice. Synchronization does not echo another callback. Invalid storage is repaired; unavailable storage permits an in-memory choice.
