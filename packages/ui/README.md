`mountGameUi(root, callbacks)` mounts the responsive game shell, menus, settings, HUD, room invites, and results. The UI consumes `UiModel`; its snapshot and scores are read-only projections. Nicknames, errors, room codes, and score rows are written as text, never HTML.

The quick controls card appears for the first **eight seconds of active keyboard/controller play per mounted page**. Briefings, countdowns, menus, hidden tabs, touch mode, authoritative pause, and interrupted connections suspend its remaining time. HUD updates, device switches, and later dispatches do not restart it. The card follows the local car using the existing viewport/suspect-marker avoidance, shows the current dispatch lesson, and hides fire until the room unlocks guns. After it disappears, choose **CONTROLS HELP** from the home, pause, results, or campaign briefing menu for the complete layouts and current lesson. Keyboard arrows/Enter and controller menu navigation reach the same action; Escape/controller Back returns to the previous menu. The guide stays open until closed and disables driving through the existing menu callback. Help also respects the unarmed opener and gun unlock.

Both layouts use original DOM/CSS graphics: raised keyboard keycaps, circular controller face buttons, a left stick, triggers, a bumper, and a menu button. Help shows both layouts; the temporary card follows the active device. Keyboard graphics follow current bindings, including remaps, and every action retains a text label. Controller graphics describe the standard mapping using A/X/Y labels. No downloaded artwork or new dependency is needed. The guide scrolls vertically on narrow screens. Generic touch controls share the existing device-independent driving actions. `UiSettings.controlScheme` persists Automatic/Touch/Controller/Keyboard. UI owns pointer capture, independent touch IDs and pad geometry, emitting `onTouchInput(TouchControls)`; input owns normalization, action edges and recovery timing. Wire `onTouchCancel` to input reset and input's `onReset` to `resetTouchControls()`. Stale moves after focus/menu/resize/device changes cannot restore held touches. The overlay hides during menus, briefings, results and interrupted connections. Drive with the left pad and hold Fire/Drift on the right; Drift + Fire permits both with one thumb. Compact layouts preserve health, 44px targets and separation from driving HUD. Safe-area insets reserve system edges. Run `pnpm exec playwright test tests/e2e/touch.spec.ts` for Chromium-emulated touch, synthetic-controller handover, persistence, cancellation/resize safety and 1024×768/844×390/390×844 captures under `work/`. The app supplies one `onPlay({roomId,nickname,vehicleBodyId})` callback plus start, resume, leave, rematch, activity and settings callbacks. `onMenuVisibility` disables gameplay input; `isMenuOpen()` distinguishes menus from the briefing for server presence. Authoritative pause state explains solo pause versus a live room with backup. Session failures appear in the current menu without requiring developer tools.

The labeled touch overlay replaces the floating keyboard/controller card in touch mode. Fire and Drift + Fire follow the dispatch-3 gun unlock; the first dispatch remains unarmed. Test contexts explicitly emulate `navigator.maxTouchPoints` from the requested `hasTouch` setting, because installed Chrome may otherwise expose the host's real touchscreen to desktop scenarios.

Fresh storage receives a clean original random callsign from `randomCallsign()`. Generated, rerolled, and custom identities persist as `{ nickname }` under `fender-callsign-v1`; the same shared nickname sanitizer bounds names to 20 characters before dispatch. The home-only `REROLL CALLSIGN` control always chooses a different name, including a bounded fallback when randomness repeats. Editing a callsign changes the next dispatch request; it does not rename an active network player. Missing, malformed, or unavailable storage keeps the UI usable. Initial menu focus remains on `HIT THE STREETS`.
