# Dispatch interface

Reviewed: 2026-10-25 for `arcade-v11` / protocol 3. *The dispatch desk supplies clues, car keys and a suspiciously cheerful damage report.*

`mountGameUi(root, callbacks)` mounts the responsive game shell, menus, settings, HUD, room invites, and results. The UI consumes `UiModel`; its snapshot and scores are read-only projections. Nicknames, errors, room codes, and score rows are written as text, never HTML.

The app supplies one `onPlay({roomId,nickname,vehicleBodyId})` callback plus start, resume, leave, rematch, activity and settings callbacks. `onMenuVisibility` disables gameplay input; `isMenuOpen()` distinguishes menus from the briefing for server presence. Authoritative pause state explains solo pause versus a live room with backup. Session failures appear in the current menu without requiring developer tools.

Fresh storage receives a clean original random callsign from `randomCallsign()`. Generated, rerolled, and custom identities persist as `{ nickname }` under `fender-callsign-v1`; the same shared nickname sanitizer bounds names to 20 characters before dispatch. The home-only `REROLL CALLSIGN` control always chooses a different name, including a bounded fallback when randomness repeats. Editing a callsign changes the next dispatch request; it does not rename an active network player. Missing, malformed, or unavailable storage keeps the UI usable. Initial menu focus remains on `HIT THE STREETS`.

Every campaign dossier includes shared `getBossTactics(dispatchIndex)` information: authored difficulty, driving style, weapon family, and counterplay. The four ringleaders have a stronger visual treatment; the six crew also disclose their gentler attack profiles. The description is authored alongside actual gameplay tuning, so the UI does not invent weaknesses or imply invisible grenade homing.

Callsign fixture: `node packages/ui/dev/callsigns-smoke.mjs` checks fresh variety, default focus, controller reroll, constant-random fallback, custom/reload/dispatch/leave persistence, malformed/overlong storage, and mounting with unavailable storage. The real app scenario is `tests/e2e/callsigns.spec.ts`. `campaign-smoke.mjs` checks all ten shared tactics/difficulty descriptions. Set `CAPTURE_UI=1` for the callsign fixture or `CAPTURE_BOSS_COMBAT=1` for campaign tactics portraits; these write labeled fixture images to original-machine absolute paths ending in `outputs/boss-combat`, as noted below.

Online leaderboards and results show every player's authoritative `pingMs`, including the local player's, with a visible `PING / ms` heading and accessible per-name readouts. Unknown values appear as `—`; only legacy local fixtures omit the latency column. Results continue following new measurements rather than freezing the first reading.

The persistent header shows a Wi-Fi icon and text for connecting, connected, reconnecting, and connection loss. Reconnecting is amber; disconnected/error states use a slashed icon and `Connection lost`. Accessible names and text convey the state without relying on color. Returning to a connected state clears the slash; legacy local fixtures use their neutral local-dispatch label.

Call `update(model)` at HUD cadence. `navigate(action)` accepts keyboard/controller menu actions. `showMenu`, `isMenuVisible`, `getSettings`, `setSettings`, and `dispose` complete the facade. Imported CSS has scoped `fo-` classes, reduced-motion support, and system font fallbacks. No external font stylesheet or font download is requested.

Call `setTargetIndicator(indicator | null)` every rendered frame. `TargetIndicator` supplies canvas-normalized `x`/`y`, clockwise angle from up, `offscreen`, and `distanceMeters`. The UI retains one DOM badge, changes its position/text without layout reads, applies the new position directly on every call with no CSS transition (a transition retargeted every frame makes Blink's style recalculation grow for the whole dispatch; `tests/e2e/target-badge-performance.spec.ts` guards this), and shows an outlined `WANTED SUSPECT` badge on screen or stacked directional chevrons with `SUSPECT` and meters off screen. The label remains upright as the arrow turns. Safe border reserves are 84px horizontally, 150px at the top on desktop (104px at widths up to 740px), and 210px above the bottom; these clear the timer/objective and lower instruments. Reduced camera motion and the OS reduced-motion preference remove the arrow bobbing. Home, menus, lobby/countdown/results, missing/completed pursuits, and interrupted online connections hide the indicator.

Campaign pursuit explicitly says `APPREHEND <NAME>`. Automatic arrest instructions, the server's local eligibility guidance and local progress explain how. A persistent floating keycap/controller card follows the player and reflects remapping; fire appears from dispatch 2. Briefings show both actual car previews and the current [tutorial lesson](../../spec/TUTORIAL.md). Results distinguish arrest/wreck outcomes, name the officer and retain earned-only clues.

Pursuit browser fixture: `node packages/ui/dev/pursuit-smoke.mjs` starts and closes its own server on 5187. It verifies local/rival progress, authoritative winner and escape results, solo completion/new dispatch, target visibility, accessible distance, all four screen edges after 1440×900/960×640/520×580 resizing, unchanged DOM nodes, no per-frame rectangle measurements, reduced motion, and explicit north/southwest HUD overlap regressions. Set `CAPTURE_UI=1` for intermediate screenshots under `work/`. This is a DOM fixture; native projection and live multiplayer are validated separately by the renderer and app suites.

The garage assigns one valid random body on fresh storage and persists `{ vehicleBodyId }` under `fender-garage-v1`. `getVehicle()` returns the assignment; `onPlay` includes it as `vehicleBodyId`. `onVehicleChange(id)` reports reassignment to a different body. Home and every connected campaign briefing allow reassignment in every server room; reconnecting/disconnected states, countdown, live play and results lock it. Lobby snapshots may supply `selectedVehicleBodyId` to synchronize authority. A stale lobby snapshot cannot undo a pending selection. Reconnect/session-epoch changes discard the pending request and resynchronize the confirmed body; leaving the lobby reconciles it once, while later live snapshots preserve the saved choice. Synchronization does not echo another callback. Invalid storage is repaired; unavailable storage permits an in-memory choice.

`isMenuVisible()` and `onMenuVisibility` include every interactive campaign briefing even though the full menu panel is hidden. This keeps driving input neutral and routes keyboard/gamepad actions to garage/start/invite controls. The app supplies selected and suspect bodies and their gun fittings to two isolated garage camera views. The UI shows its shared profile name, role, armor, top speed and acceleration/handling meters; HUD integrity is normalized against that body's maximum health.

Campaign snapshots project the [authored catalog and rules](../../spec/CAMPAIGN.md). The briefing puts a 96px original target portrait, assigned suspect car, ten-step tracker and earned casefile beside the player's garage. Reassignment is allowed at every briefing. `onStartRound` starts the current stage; `onRematch` opens the next briefing, retries the current stage after timeout, or resets a completed campaign. The app retains the same room session across these callbacks. Any connected officer can proceed; disconnected users see reconnect guidance. No client-supplied campaign outcome is trusted.

The room flow exposes Hit the streets and one persistent Invite URL button. The app assigns a room URL on bare visits; players share that address or copy it through the button, then friends enter the same campaign. There is no room-code field or create/join mode menu. An accessible idle warning provides Stay on patrol; intentional `idle-timeout` explains re-entry. Repeated status refreshes preserve keyboard focus. Casefiles use the outcome’s immutable credited callsign after departure. [Room sessions](../../spec/ROOM_SESSIONS.md) records retention and pause semantics.
