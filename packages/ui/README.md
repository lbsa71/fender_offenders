# Dispatch interface

`mountGameUi(root, callbacks)` mounts the responsive game shell, menus, settings, HUD, room invites, and results. The UI consumes `UiModel`; its snapshot and scores are read-only projections. Nicknames, errors, room codes, and score rows are written as text, never HTML.

The app supplies semantic callbacks for practice/create/join, start round, resume, leave, rematch, and settings. `onMenuVisibility` must disable gameplay input; local practice can pause its simulation, while online simulation continues. UI copy makes this distinction explicit. Session failures appear in the current menu without requiring developer tools.

Fresh storage receives a clean original random callsign from `randomCallsign()`. Generated, rerolled, and custom identities persist as `{ nickname }` under `fender-callsign-v1`; the same shared nickname sanitizer bounds names to 20 characters before dispatch. The home-only `REROLL CALLSIGN` control always chooses a different name, including a bounded fallback when randomness repeats. Editing a callsign changes the next dispatch request; it does not rename an active network player. Missing, malformed, or unavailable storage keeps the UI usable. Initial menu focus remains on `HIT THE STREETS`.

Every campaign dossier includes shared `getBossTactics(dispatchIndex)` information: authored difficulty, driving style, weapon family, and counterplay. The four ringleaders have a stronger visual treatment; the six crew also disclose their gentler attack profiles. The description is authored alongside actual gameplay tuning, so the UI does not invent weaknesses or imply invisible grenade homing.

Callsign fixture: `node packages/ui/dev/callsigns-smoke.mjs` checks fresh variety, default focus, controller reroll, constant-random fallback, custom/reload/dispatch/leave persistence, malformed/overlong storage, and mounting with unavailable storage. The real app scenario is `tests/e2e/callsigns.spec.ts`. `campaign-smoke.mjs` checks all ten shared tactics/difficulty descriptions. Set `CAPTURE_UI=1` for the callsign fixture or `CAPTURE_BOSS_COMBAT=1` for campaign tactics portraits; these captures go under `outputs/boss-combat` and are labeled as authored fixtures.

Online leaderboards and results show every player's authoritative `pingMs`, including the local player's, with a visible `PING / ms` heading and accessible per-name readouts. Unknown values appear as `—`; solo practice omits the latency column. Results continue following new measurements rather than freezing the first reading.

The persistent header shows a Wi-Fi icon and text for connecting, connected, reconnecting, and connection loss. Reconnecting is amber; disconnected/error states use a slashed icon and `Connection lost`. Accessible names and text convey the state without relying on color. Returning to a connected state clears the slash; local practice uses its neutral local-dispatch label.

Call `update(model)` at HUD cadence. `navigate(action)` accepts keyboard/controller menu actions. `showMenu`, `isMenuVisible`, `getSettings`, `setSettings`, and `dispose` complete the facade. Imported CSS has scoped `fo-` classes, reduced-motion support, and system font fallbacks. No external font stylesheet or font download is requested.

Call `setTargetIndicator(indicator | null)` every rendered frame. `TargetIndicator` supplies canvas-normalized `x`/`y`, clockwise angle from up, `offscreen`, and `distanceMeters`. The UI retains one DOM badge, changes its position/text without layout reads, applies the new position directly on every call with no CSS transition (a transition retargeted every frame makes Blink's style recalculation grow for the whole dispatch; `tests/e2e/target-badge-performance.spec.ts` guards this), and shows an outlined `WANTED SUSPECT` badge on screen or stacked directional chevrons with `SUSPECT` and meters off screen. The label remains upright as the arrow turns. Safe border reserves are 84px horizontally, 150px at the top on desktop (104px at widths up to 740px), and 210px above the bottom; these clear the timer/objective and lower instruments. Reduced camera motion and the OS reduced-motion preference remove the arrow bobbing. Home, menus, lobby/countdown/results, missing/completed pursuits, and interrupted online connections hide the indicator.

Campaign pursuit says `FIRST TO RESOLVE DISPATCH` online and `ARREST OR WRECK THE TARGET` solo. The three-second close/matched-speed progress bar always shows the local contender's arrest progress; a rival's leading progress is never presented as the local player's. Results and the ten-step tracker distinguish green arrest checks from amber wreck marks, name the resolving officer, and show earned story clues. Timeouts add no outcome or clue. Combat points remain independently ranked. Generic snapshots without campaign state preserve the earlier `FIRST TO APPREHEND` single-pursuit fixture flow.

It verifies local/rival progress, authoritative winner and escape results, solo completion/new dispatch, target visibility, accessible distance, all four screen edges after 1440×900/960×640/520×580 resizing, unchanged DOM nodes, no per-frame rectangle measurements, reduced motion, and explicit north/southwest HUD overlap regressions. The garage assigns one valid random body on fresh storage and persists `{ vehicleBodyId }` under `fender-garage-v1`. `getVehicle()` returns the current assignment; `onPlay` includes it as `vehicleBodyId`. `onVehicleChange(id)` reports user reassignment, always to a different body. Home and the connected online lobby allow reassignment; reconnecting/disconnected states, countdown, live play and results lock it. Lobby snapshots may supply `selectedVehicleBodyId` to synchronize the authoritative choice. A stale connected-lobby snapshot cannot undo a pending user selection. Reconnect/session-epoch changes discard that pending request and resynchronize the confirmed body; leaving the lobby reconciles an accepted or rejected pending selection once, while later in-round snapshots preserve the saved choice. Synchronization does not echo another selection callback. Invalid/corrupted saved values are repaired; unavailable storage still allows a valid in-memory choice.

`isMenuVisible()` and `onMenuVisibility` include interactive online lobbies and solo campaign briefings even though the full menu panel is hidden. This keeps driving input neutral and routes keyboard/gamepad actions to garage/start/invite controls. The app supplies the selected body to the renderer's garage preview. The UI shows its shared profile name, role, armor, top speed and acceleration/handling meters; HUD integrity is normalized against that body's maximum health.

Campaign snapshots project the [authored catalog and rules](../../spec/CAMPAIGN.md). The briefing puts a 96px original target portrait, assigned suspect car, ten-step tracker and earned casefile beside the player's garage. Reassignment is allowed at every briefing. `onStartRound` starts the current stage; `onRematch` opens the next briefing, retries the current stage after timeout, or resets a completed campaign. The app retains the same local simulation/online session across these callbacks. The online creator controls progression; other players see waiting text. No client-supplied campaign outcome is trusted.
