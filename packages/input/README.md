# Input adapter

Reviewed: 2026-10-24 for `arcade-v8`. *A released accelerator should stay released, even when the paperwork loses focus.*

2026-10-25 touch extension: `InputSettings.controlScheme` persists `auto`, `touch`, `gamepad` or `keyboard`. Automatic starts with touch when `navigator.maxTouchPoints > 0`, otherwise keyboard; fresh keyboard/controller use switches devices, and touching the play area returns to touch. Explicit schemes admit only that device's driving input. `setTouchState(TouchControls)` accepts normalized held actions from UI; input owns siren edges and the one-second recovery hold. Device changes clear previous held state. `onReset` clears UI pointer ownership alongside session `onNeutralize`, including viewport resize on touch. Input continues to poll controller menus independently. No user-agent or platform name is used. Physical iPad/Android/controller acceptance remains open.

`createInputSource(options)` implements the shared `InputSource` contract. It starts disabled. The app enables it after a session starts and disables it while menus are visible. Call `pollMenus()` once per animation frame, including while gameplay is paused, and call `sample()` once per simulation tick. Sampling also polls devices, so contract-only consumers still receive gamepad input.

Pass `onNeutralize` to send immediate session neutralization on blur, hidden tab, controller loss, menu entry, or settings changes. Returning focus, reconnecting a controller, or closing menus does not replay held controls. Keyboard input needs a new press; a controller must return to neutral. The adapter removes all listeners on `dispose()`.

`onMenuAction` emits `up`, `down`, `left`, `right`, `confirm`, `back`, or `pause`. Standard-mapped controllers are supported. Unknown mappings are reported through `getStatus().unsupportedPad`, with keyboard fallback. `getStatus()` also reports the active device, focus, and recovery hold progress. `setSettings` validates and persists dead zones, sensitivity, steering ramp, and keyboard mappings. Persistence is optional when browser storage is blocked.

Touch and the left stick request a screen direction. `TouchControls.driveX/driveY` use right/down-positive axes; a shared radial stick dead zone and normalized magnitude control acceleration without diagonal boost. Each sample resolves the shortest heading error against `drivingYaw()`, with `directionToYaw(x,y)` supplied by the renderer to account for camera projection and reflected world X. The app reads the current predicted yaw on every input tick, including timer batches, rather than using stale snapshots or sampling extra render frames. The ordinary car controller turns toward that heading; tight turns ease acceleration but retain enough power to turn from rest. Release coasts. Keyboard remains vehicle-relative; triggers retain optional throttle/brake alternatives, combined by maximum strength.

`InputController` is the pure device state machine used by the browser adapter and unit tests. Run `pnpm exec vitest run packages/input/src/input.test.ts` for safety/normalization coverage, including directional heading feedback, radial dead zones, analog precision, trigger coexistence and held-stick focus/disconnect safety. Browser-level controller testing uses injected standard-mapped gamepads; physical-controller acceptance remains open.

The bicycle tyre controller belongs to simulation: handbrake/power/flick can initiate a drift, centered stick holds its angle and counter-steer trims it. Input keeps one normalized action contract for every car and device. Campaign briefings are menus, so garage/start navigation must not leak into throttle/fire. The app may run fifteen local catch-up ticks in a frame but only four online input ticks; `sample()` consumes each edge once across those steps.

Next acceptance is real-controller hotplug, remap/focus recovery and a complete campaign drive on named browser/OS combinations. See [the acceptance queue](../../IMPLEMENTATION_PLAN.md#next-acceptance-work). Synthetic backup is useful; the actual gamepad still has to report for duty.
